One-on-one with Prof. Sugiyama · November 2026

Tycho: a calibrated survey of how networks learn

We train thousands of small networks under systematically varied conditions and measure each whole training run with one calibrated instrument, refined information. Every measurement answers one question: which variables start to interact, at which order, at which training step?

Two pictures from astronomy

A spectrometer measures one object. A survey measures many objects the same way.

The project borrows two ideas from astronomy, so a few words like spectrum, survey and catalog come up. Here is what each one means in our setting.

Why

Training dynamics has many phenomena and no common ruler

Grokking, double descent, staged in-context learning and the hidden progress of parity learning were each found in one particular setting. Rarely has anyone measured whether they persist under other configurations or where their boundaries lie, and never with a calibrated instrument. The three branches of LLM science are at different stages:

Object of studyWhere it standsAstronomical analogue
Trained models across scaleEmpirical laws (scaling laws), no accepted mechanismafter Kepler, before Newton
What is inside one modelNew instruments (probes, SAEs, attribution graphs), few regularities yetGalileo's first telescope
How training unfolds in timeScattered observations, unknown errors, not comparablebefore Tycho Brahe

Kepler dropped circular orbits over an 8-arc-minute discrepancy, and he could do so only because Tycho's instrument error was known to be smaller. So the plan is to calibrate the instrument first, then survey: an anomaly in the catalog means something only relative to a known error.

The instrument

Refined information, implemented as in your paper

Definition 1 of Enouen & Sugiyama (TMLR 2026), for a hierarchical collection I:

RII,S(p) = DKL(pI+S ; pI)

We use the two order-invariant values of Appendix C.1:

  • RImargS (I = P(S) − S) as the survey's per-subset "spectral line". It needs only the small table of S, so we can scan every subset up to order 4–5 of tens of variables.
  • RIcondS (I = P([d]) − {T ⊇ S}), reported for small variable sets.

Complete chains from {∅} decompose D(p; u) exactly. The numerical error of the decomposition is 2·10⁻¹¹.

Estimation from N probe samples:

G² = 2N · RÎ ~ χ²df, df = Π(ki − 1)

This gives a p-value per subset and a bias correction RÎ − df/2N. Benjamini–Hochberg runs across subsets at each checkpoint. A subset is detected when q ≤ 0.01 and RI ≥ min_effect, where min_effect comes from calibration.

A finding for the variable question. Binarising a Gaussian that has only pairwise correlation creates higher-order interactions in the bits. At ρ = 0.8, median thresholding gives order-4 RI = 1.4·10⁻³ nats, above the detection threshold (order 3 is exactly 0 by sign symmetry). A positive control is a task whose interaction structure we set ourselves. Each control below is one training run, with RI measured at 30 checkpoints during training.

Exactly one subset is detected at the end: the planted 4th-order one, at 0.688 nats against log 2 = 0.693. No pair or triple inside it is ever active, so this is pure synergy. The interaction switches on between steps 975 and 1,363 (shaded), before test accuracy reaches 90 % at step 1,538. MLP width 512, SGD, lr 0.05; step 0 is drawn at 1.

Token language with planted orders: a 2nd-order and a 3rd-order dependence

order 2: {x[t−1], x̂} order 3: {x[t−1], x[t−3], x̂} true values from the source

Binary tokens; the next token depends on x[t−1] (coupling 1.0) and on x[t−1]·x[t−3] (coupling 0.8). The network learns the pairwise term first (from step ≈ 14) and the three-way term later (onset between steps 69 and 96, still growing at 10k): low order before high order, as predicted. At the end, only these two of 21 candidate subsets are detected, at 0.1727 and 0.1142 nats against true values of 0.1728 and 0.1209.

What runs on the Mac mini, 24×7

An unattended observatory

  1. Sky definitiontasks × knob grids × seeds
  2. Schedulercoarse grid → boundaries → more seeds
  3. Workerstrain + photometry, one CPU core each
  4. CatalogSQLite + per-run files
  5. RI follow-upbit-exact replay, dense checkpoints
  6. Events → transientspushed to a phone
  7. Claude agentnightly QC + proposals, weekly report
  8. Data releaseversioned, checksummed

One advantage over astronomy is that the sky can be re-observed. Every run replays bit-for-bit on CPU, so an interesting run can be observed again later with denser RI checkpoints around its transition, or perturbed and re-run, which turns observation into experiment.

Status: every module is built. The tests check the paper's examples, crash and resume, graceful shutdown, and parallel workers; all 654 pass. One end-to-end survey run completed. The nightly agent can only read the catalog and make small, capped, audited writes.

Questions for you

Where your judgement would help most

  1. Which value for events? We detect events with RImarg (cheap, with a χ² null) and report RIcond only for small sets. Is this the right division, or should RIcond onsets be tracked as a separate kind of event?
  2. Higher orders with sparse tables. Beyond exhaustive scans of small subsets, would the MAHGenTa sampling approach help for larger variable sets?
  3. Discretisation artefacts. Is there an information-geometric way to correct for interactions created by thresholding, for example by comparing against the projection of a latent model?
  4. Token variables. Should they stay categorical (df grows as Π(k−1)) or be binarised?
  5. Testing over time. Is per-checkpoint BH plus a persistence rule adequate, or should onsets use a sequential or change-point test?
